# Evaluation Methodology

A transaction is treated as an alert when the rule engine returns REVIEW or DECLINE. Alert outcomes are compared with the synthetic `label_is_fraud` field.

- True positive: labelled fraud and alerted.
- False positive: labelled legitimate but alerted.
- True negative: labelled legitimate and not alerted.
- False negative: labelled fraud and not alerted.
- Precision = TP / (TP + FP).
- Recall = TP / (TP + FN).
- False-positive rate = FP / (FP + TN).

## Interpretation cautions
Synthetic labels are generated by the same broad patterns the example rules seek to identify. This can make the exercise circular and overly optimistic. The metrics demonstrate implementation of an evaluation workflow; they do not establish real-world effectiveness. A stronger second iteration should use independently generated fraud patterns, time-based holdouts and scenario-specific analysis.
